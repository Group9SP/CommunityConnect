# F4.2.2 Admin Review Queue — What You Need To Do

The code for the admin review queue (routes, components, hooks, and migration) is already implemented in the repo.  
This file is trimmed down to only the manual steps you still need to perform.

---

## 1. Apply the new migration

Make sure your Supabase database has the latest migrations applied (including `20260303000000_admin_review_queue.sql`), using your normal workflow, for example:

- `supabase db push`  
  or  
- Run migrations from your deployment pipeline / Supabase UI.

Once applied:
- The `admin` role value exists in the `app_role` enum.
- RLS and trigger logic are in place so only admins can change `verification_status`.

---

## 2. Create at least one admin user

After the migration is applied, promote one or more existing users to admin by inserting into `user_roles`:

```sql
INSERT INTO public.user_roles (user_id, role)
VALUES ('<auth-users-uuid>', 'admin')
ON CONFLICT DO NOTHING;
```

Replace `<auth-users-uuid>` with the `id` from `auth.users` for the account you want to be an admin.

You can run this from:
- Supabase SQL editor, or
- Any database migration / admin tool you already use.

> Keep admin assignment as a manual/ops-only step; do not expose it through the public UI.

---

## 3. Verify the feature end-to-end

With an admin user created:

1. Sign in as that admin in the app.
2. Use the avatar menu (top-right) and click **“Review queue”**, or go directly to `/admin/review`.
3. Confirm you can:
   - See businesses whose `verification_status` is `pending`.
   - Approve a business and then see it show up in the regular browse flow.
   - Reject a business and see it leave the pending list.
4. Sign in as a non-admin user and confirm:
   - `/admin/review` is blocked by the admin guard.
   - The “Review queue” menu item does not appear in the user dropdown.

These checks are the only remaining actions required to finish F4.2.2.***
